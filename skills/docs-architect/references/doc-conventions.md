# Documentation taxonomy & anti-drift conventions

The operating model for agent-ready documentation. Grounded in public standards, not invented:
- **Diátaxis** (Daniele Procida) — the 4 documentation types: tutorial · how-to · reference · explanation. https://diataxis.fr
- **ADR** (Architecture Decision Records, Michael Nygard 2011) — the decision log. https://adr.github.io
- **AGENTS.md** (2026 de-facto agent-instruction standard) — *"a briefing, not documentation"*; **"stale structural references actively mislead — repo-structure docs become a liability when code changes."** https://agents.md

## The core idea: two axes

1. **Diátaxis axis** — what cognitive need the doc serves (learn / do / look up / understand).
2. **Maintenance axis** — **GENERATED** (derived from code, regenerated on push) vs **AUTHORED** (written by hand).

> **The drift problem, named:** drift happens when an AUTHORED doc holds a fact that should be GENERATED (a function count, an inventory, a module map). Those facts age the moment code changes. Diátaxis says reference *"reflects the structure of the thing it describes"*; AGENTS.md says stale structure *"actively misleads"*. → such facts are **generated or omitted, never hand-copied.**

## The classes (taxonomy + naming + placement)

| Clase | Diátaxis | Mantención | Ubicación | Naming | Ejemplo nuestro |
|---|---|---|---|---|---|
| **reference** | Reference | **GENERADA** (push) | `docs/reference/` | `<topic>.md` + banner | inventario API/RPC, mapa de módulos, conteos, schema |
| **canon** | Explanation | AUTORADA · 1 dueño/tema | `docs/arquitectura/` | `<topic>.md` | el contrato (el *porqué*), DONDE_VA_LA_LOGICA |
| **extraction-contract** | Explanation | AUTORADA · changelog rastrea schema del código | `docs/arquitectura/` | `<topic>.md` | ledger de OCR/parsers: `OCR_EDGE_FUNCTIONS.md` |
| **decision** | (decision log) | AUTORADA · append-only | `docs/decisions/` | `NNNN-kebab-title.md` | hipótesis A–G, decisiones tomadas |
| **runbook** | How-to | AUTORADA | `docs/runbooks/` | `<verbo>-<sustantivo>.md` | procedimientos operativos |
| **briefing** | — | AUTORADA · corta | `AGENTS.md` / `CLAUDE.md` (raíz) | — | reglas críticas + comandos + links |
| **archive** | — | congelada | `docs/_archive/` | fecha permitida | session-logs, reportes fechados |

## Naming rules

- **kebab-case**, descriptivo. **Sin fechas** en `canon`/`reference` (lo fechado va a `archive`).
- **ADRs:** secuencia con padding `NNNN-title.md` (`0001-snapshot-fork.md`). Append-only: no reescribir, **supersede** con un ADR nuevo.
- **reference (generada):** banner obligatorio en la 1ª línea — `<!-- GENERATED by <generador> — do not edit by hand -->` — y `generado: true` en frontmatter.
- **Frontmatter requerido** en todo doc: `clase` (reference|canon|decision|runbook|archive) + `estado` (vigente|borrador|deprecado).

## Las reglas anti-drift (el objetivo)

1. **Los hechos de referencia se GENERAN, nunca se copian a mano.** Conteos, inventarios, mapas de módulos, schema → `docs/reference/` generado, o se omiten. (Diátaxis: reference refleja la cosa; AGENTS.md: estructura stale confunde.)
2. **El briefing es briefing, no documentación.** `AGENTS.md`/`CLAUDE.md`: reglas críticas primero, comandos exactos, **links** al canon. Corto. No re-enuncia el canon.
3. **Un solo canon por tema.** Lo demás LINKEA, nunca re-enuncia. Duplicación = drift garantizado.
4. **Decisiones = ADRs append-only.** No reescribir la historia; superseder.
5. **Colocación.** El doc vive cerca de lo que documenta; la referencia se genera del código.
6. **Contrato de extracción (OCR/parsers).** Un `canon` cuyo changelog rastrea un schema derivado del código (el `JSON_SCHEMA` de un OCR/parser) tiene una superficie de drift *triple* — schema (código) ↔ columnas destino (DB) ↔ changelog (doc) — que ningún otro doc tiene. Auditarla es su propia dimensión: ver [`extraction-contract-docs.md`](extraction-contract-docs.md).

## Cómo docs-architect lo hace cumplir (checks)

- **Clase declarada:** todo doc declara `clase` en frontmatter → flaggear faltante o ubicación que no matchea la clase.
- **Drift generado/autorado (el check clave):** flaggear (a) docs AUTORADOS que contienen hechos generables (conteos, inventarios, estructura) → mover a `reference` generado o reemplazar por link; (b) docs de `reference` escritos a mano que deberían generarse.
- **Briefing limpio:** flaggear `AGENTS.md`/`CLAUDE.md` que re-enuncian canon en vez de linkear, o que tienen estructura/comandos stale.
- **One-canon:** misma regla/tema en N docs autorados → recomendar canon único + links (no N copias).
- **Comandos sobre prosa:** para build/test/lint, comando exacto > guía en prosa (AGENTS.md).
